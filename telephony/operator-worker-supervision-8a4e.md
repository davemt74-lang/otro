# Operator Phase 8A.4E — supervised HomeServer reporting service

Dependent on HomeServer #379 and Cloud #857. Browser-independent startup is attached to the existing HomeServer application lifespan, not to a new Windows service. Default is disabled. For an explicitly approved non-billable staging test, launch HomeServer with VP3_OPERATOR_WORKER_ENABLED=1 and VP3_OPERATOR_CLOUD_ORIGIN=https://vp3.me (or your exact deployed trusted HTTPS origin). Cloud must have installed its schema, explicitly enabled registration and granted the paired device. No automatic grant, pairing, credential file, paid resources, call dispatch or media connection.

The paired reader rechecks the existing protected session, read-only remote identity, enabled exact HTTPS bridge and active local VP3 approval before/after exchanges. A worker thread holds one in-memory handle. It verifies registration, sends heartbeats every 20 seconds after acknowledgement, and drops current status during exchange/uncertainty. The read-only report is stale after 25 seconds without a verified acknowledgement (or earlier lease expiration), uses monotonic freshness plus signed wall-clock bounds, and omits capabilities when not current. No credential, account/device ID, origin, call or raw error details are reported.

Opening failures use 5/10/20/40/60-second capped backoff. An unresolved signed request may be retried only byte-for-byte at 2/4/8-second delays and only if the protocol still considers it fresh. After exhausted/invalid recovery, close the handle and wait at least 130 seconds from the last attempt before a new boot. The Cloud registry independently rejects replacement of a live boot. There is no fallback to a new signed sequence, carrier retry or live claim. On shutdown, retire only an exact current reporting handle once; pending/stale registrations are left to lease expiry, never guessed successful. Stop sets a fence and joins at most eight seconds; a blocked daemon is never replaced while alive, status is non-current. Per-operation TLS timeouts remain in the transport; a hard process-level total network deadline is not implemented.

Local /api/v1/status gains an additive redacted operator_worker report. It does not prove live connection, actual execution, device/audio readiness, or current remote consent. Cloud Brain/Chat status projection and real HTTPS acceptance remain separate integration gates. No new inbound listener or LiveKit changes. Tests are discovered by the existing Phone Gateway CI; fake handles exercise the real wire client and scratch authority, without network calls or real credentials. Existing HomeServer lifespan/packaging checks also apply.
