# Operator 8A.5A — synthetic participant floor and serialized speech

A fixture-only controller now binds a synthetic owner/Agent/conversation/contact/workspace occurrence, exact Twilio stream and approved consent revision. It requires both explicit fixture approvals and rechecks the same authority before accepting or publishing any media. No DTMF event can establish consent or grant a speaking floor. An explicit synthetic voice-activity input can reserve the caller floor; only one bounded Agent turn is allowed. Turn permits bind a random token, media generation, deadline and sample allowance (maximum 20 seconds of 8 kHz PCM). The existing media adapter enforces bounded segments and one in-flight mark.

All simulated output, interruption and owner stop/takeover operations serialize under one local lock. No raw outbound batch escapes: a bounded metadata-only trace and opaque mark receipt allow non-billable regression tests. Barge-in invalidates old synthesis, clears playback, and requires the mark to reconcile before another turn. Cleared marks never prove hearing. Revoked, replaced or unavailable authority, clock rollback, expired turn/lease and transport errors fence media. Owner takeover only stops Agent audio and closes the fixture; it does not prove a human joined, the carrier ended, or a successful conversation.

Run python -m unittest discover -s tests -p 'test_telephony_operator_participant_control.py' -v. The suite covers consent and revision checks, single floor, backpressure, stale permits, concurrent takeover/publication ordering, sample/turn bounds, DTMF, timeout and redaction. All fixtures are synthetic; no carrier, recording, model, network listener, speech recognition, actual conference join, scheduling or LiveKit changes. A deployed distributed authorization and socket executor, independently verified recipient consent, real human transfer/conference route, media and speech adapters, and physical provider acceptance remain separate gates.
