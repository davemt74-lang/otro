# Operator 8A.5B — controlled two-human conference handoff reference

The native Twilio path does not treat bidirectional Media Streams as a multiparty conference. A synthetic handoff grant binds the existing caller stream, owner-controlled existing carrier leg, account, exact principal/occurrence, separate owner and recipient approvals, revision and deadline. A one-use description redirects the existing owner leg to a uniquely named private conference (muted, waiting, no recording, max two). Verify that exact leg before touching the caller. The Agent's speech is then permanently paused and buffered audio cleared, without closing the original stream prematurely. A cleared mark must reconcile before reserving caller redirect. Both legs begin muted; exact conference membership and original stream stop evidence must be verified before individual mute/unmute descriptions. Disconnect is separately reserved; only exact completed conference evidence proves conference closure, never carrier-terminal state. Unknown or mismatched mutation evidence is fenced for review, not automatically replayed. No automatic Agent resumption or live listening to the two-person conference exists in this slice.

Twilio contract references: https://www.twilio.com/docs/voice/twiml/conference ; https://www.twilio.com/docs/voice/api/conference-participant-resource ; https://www.twilio.com/docs/voice/api/call-resource . Real call updates and conference behavior must be verified against deployed Twilio in staging. This code contains no carrier client, real consent proof, durable external reservation or network sender. The actual service must authenticate an existing owner leg, persist one-use dispatch intent, reconcile REST evidence, bind signed callbacks, enforce time and budget, and handle revocation and terminal call outcomes. A future three-party Agent route requires separately verified consent and media topology. No LiveKit changes, actual dialing, recordings or paid requests.
