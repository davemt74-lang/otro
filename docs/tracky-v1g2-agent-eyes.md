# Tracky 1G2 — Agent Eyes supervised live observations

**Production ownership:** VP3 HomeServer, not the standalone Tracky development script. The existing `tracky_native_managed_session` worker remains the only supervised native-camera loop. Agent Eyes uses it with a distinct `owner_surface`, while both modes use the canonical Tracky provider and existing exclusive native camera driver lock.

**Default:** off. Owner must first perform the installed HomeServer camera test, local privacy check and owner acceptance. Agent Eyes also requires fresh consent and an owner-selected local camera per session. It samples locally 1–12 times at minimum five-second intervals, has a two-minute absolute limit and a 15-second owner-presence heartbeat. No unattended startup or automatic resumption. Closing the Tracky view or hiding its initiating tab requests immediate stop; the server lease expires independently if that request cannot arrive.

**Privacy and safety:** face-region detector is not recognition. No recordings or templates persist; synthetic tests are not installed-device hardware certification. All observations pass through the existing `tracky.active_perception` ledger; Agent Chat sees passive operational status and counts only. HomeServer never advertises this temporary local owner-bound provider as remotely available to Cloud. It does not give Cloud control of camera capture.

**Agent integration:** existing Agent Chat onboarding summary includes `agent_eyes` with current operation, last observation time, presence gate, provenance through canonical request ledger and next owner action. Read-only status cannot issue a capture or extend a lease. Agent Brain's broader contextual recognition, multi-camera fusion and durable policy for unattended perception are explicitly deferred to governed 1G3, not impersonated by this section. The first owner-local, read-only integration is documented in [1G3A](tracky-v1g3-agent-brain.md); it provides recent coarse detector context only.

**Test gates:** owner authentication/CSRF, strict start validation, privacy rejection, installed-review binding, exclusive provider, shared native driver, canonical observation ledger, passive Agent status, non-biometric output, UI visible-tab owner lease and no cross-session stop. Hardware certification must run on the installed Windows HomeServer after release.

## 1G2B1: supervised resource budgets and watchdog

The original installed-device two-minute/12-observation/15-second visible-owner lease stays in force. An explicit local owner can choose a 60- or 120-second limit and a 4/8/12 CPU-second budget. CPU accounting uses the observation worker's thread CPU time; it is not system-wide process accounting. Status and the owner dashboard expose current session budget usage. The independent watchdog checks owner lease, privacy, current-model acceptance, elapsed time, CPU usage and stalled observation attempts; it only revokes, never launches or resumes capture. A stalled uninterruptible OS camera call can remain occupied, so the shared camera capture lock still blocks a fresh session until the driver returns.

This section is *not* longer-running or unattended production certification. Extended sessions beyond two minutes, background operation, recording and identification remain disabled until physical installed-device acceptance and a distinct owner-approved policy. Focused synthetic automated tests are not physical proof.

## 1G2B2: installed-device recovery checklist and redacted evidence

Owner-only Agent Eyes failures preserve their precise allowlisted terminal reason in the existing restart-safe session evidence ledger, including watchdog stalls and CPU limits; raw error text, camera frames and device identifiers are excluded. The passive recovery status exposes whether the native worker, existing provider or exclusive camera lock is still occupied. A failed/interrupted Agent Eyes session is fail-closed for new supervised capture until the installed owner inspects camera release and explicitly acknowledges the session via the authenticated local UI. Acknowledgement is durable and bound to a fingerprint of the non-identifying terminal session, not transferable to the next failed session. It **does not certify** physical isolation, alter model acceptance, bypass fresh per-session consent or authorize unattended perception. Software cannot prove that a driver has physically powered off the camera; the owner must verify on the actual installed device.

Installed owner acceptance exercise: (1) verify the tested installer/model binding and active local review; (2) begin a fresh short supervised session in the visible Tracky view; (3) use Stop and confirm active worker/provider return idle, and independently inspect the device; (4) repeat with the privacy switch and tab visibility change; (5) exercise a simulated stall in the synthetic suite, then inspect an actual incident if one occurs; (6) confirm recovery blocks start until worker/driver idle and explicit owner acknowledgement, and check no automatic resume after HomeServer restart. Record actual device measurements outside synthetic CI; do not call this physical certification until real-device results have been reviewed separately.

## 1G2B3: current-install guided owner exercise

A new owner-only exercise panel reuses the same HomeServer canonical Agent Eyes worker and existing runtime certification ledger. Only a current-process terminal Agent Eyes session that is tied to the *current* native model SHA and current owner-review record can be reported. Owner stop, actual reported privacy-switch revocation and the 15-second presence heartbeat expiry must each be completed as separate supervised sessions; the UI intentionally provides an owner-controlled pause of heartbeat traffic to test the lease without any Cloud capture route. The native capture lock/provider must be idle and the owner must personally report observing release before a stage is recorded. Reports are idempotent, local, redacted, bound to the current process, installed-model digest and review ID, and cannot be replayed after process restart/model replacement. A single stage cannot stand in for three separate session reasons.

Finishing all three stages means *current-device owner exercise reported*, not independent camera disconnect verification or permission to enable extended/unattended capture. 1G2B4 may use this as one input to a separate owner-approved extended-supervision policy after actual installed-device evaluation. No automatic activation or new camera worker is created here.

## 1G2B4: opt-in extended owner-supervised attention

Longer 5- and 10-minute budgets and up to 60 spaced observations are available **only** if the three current-install Agent Eyes owner exercises have been reported for the current reviewed detector and HomeServer process. Every extended session still requires fresh local owner approval, a visible initiating Tracky tab with the original 15-second heartbeat, the independent watchdog, strict wall-time and observation-thread CPU budgets, the physical/software privacy gate, the existing canonical Tracky perception ledger and exclusive native driver lock. No Cloud activation, identity matching, recording, automatic restart or unattended background perception is added. Generic supervised native sessions remain strictly 12 samples/two minutes; an extended Agent Eyes session cannot borrow their authority. Supported extended budgets are 300 or 600 seconds, a hard maximum of 60 observations and 5–30-second intervals; count/interval/time feasibility is checked server-side. Owner CPU budget selections are 4/8/12/20/30 thread CPU-seconds; these are not global process quotas. The installed owner exercise is *owner-reported*, not independent physical hardware certification; broader unattended perception remains disabled pending separate physical acceptance.
