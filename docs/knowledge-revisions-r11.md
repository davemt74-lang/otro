# R11 — Refine a document draft through Chat

After creating a source-cited document draft, ask **make it shorter** or **rewrite that brief in bullets**. The latest assistant reply must contain one unambiguous current new-document draft. When there are multiple proposals, quote its exact title or choose **Refine this draft in Chat** on its card. That selection includes the live editable fields and selected destination without replacing the typed composer. Older cards cannot silently select a different latest draft.

Refinement changes editable prose only. The current canonical source identities, revisions, citation labels, conversation scope and destination permissions are checked before and after inference. The model receives bounded untrusted draft/evidence text and cannot browse, run tools, choose identifiers or write records. Missing or unsupported citations and invalid output are rejected. Privacy, Knowledge-off, read-only, pairing and owner/lead boundaries remain enforced.

Each revision retains a root draft identity. Every card in that chain resolves one existing R8 exact-review identity. The first exact review freezes the chain; refinements are rejected once it exists. Old cards restore that same review, and apply retries create one canonical document. A dismissed or applied review requires an explicitly new document draft. Refinement history uses existing Chat metadata; Knowledge, indexing, approvals, project pointers and native receipts use their existing authorities. No new store or migration; native schema remains 80. Chrome advances to 22.21.0 with its existing identity key and runtime whitelist.

## Acceptance gates

1. Matching Cloud/native intent for explicit document refinements; discussion, negation, unrelated work and new-document requests retain semantics.
2. Latest owner/lead/conversation reply only; no guessed ambiguous target, stale selection or cross-context packet.
3. Bounded current edited fields and explicit destinations; all original source identities and pinned citation labels retained.
4. Strict model fields/output limits, no tools/writes, unsupported or dropped citations rejected.
5. Before/after current source, scope, destination and account authority; changed authority discards output before assistant persistence.
6. One stable review identity across original/revised cards; reviewed/applied/dismissed chains freeze, retries do not duplicate documents.
7. Mobile Cloud/native/Chrome selection, safe rendering, preserved unsent composer, edited fields and destination, reset on context change.
8. Native actual Chat/history, current pairing/privacy/read-only boundaries, truthful provider usage, no competing native Knowledge record.
9. Retained R4–R10 database, export/receipt and browser regressions; PHP/MySQL matrix and cross-system acceptance.
10. Green immutable candidate/main workflows, Windows packaged browser/recovery/installer/private-data upgrade, identical certified/merged trees and verified deploy archives.

Tests use controlled identity, model and external transport fixtures where documented. Certification covers tested software and installer behavior, not live owner accounts or hardware. Connection recovery remains on hold. Dependent task creation follows in a later section after a canonical document receipt; R11 adds only conversational refinement.
