# Agent Eyes engagement and speaker-aware listening — v1343

Introductions made through ordinary typed or transcribed Chat now save/reuse the existing participant record. A single current camera track receives a self-introduced label; it is not a biometric match or account identity. Ambiguous views, track expiry and camera Stop cancel the pending introduction. A separate explicit “remember me visually” reply to the local recognition offer, or the existing consent checkbox, saves three consistent local visual samples. Voice and cloning preferences are preserved.

The orb pulses during actual audible speech, including while a chat request is still busy. A separate speech wave leaves the red saved-recording ring intact. Camera coordinates drive smooth horizontal/vertical following with a mirrored default and small idle drift. Movement pauses on hover/focus, manual drag, reduced-motion preference, an open chat popup, multiple people, or camera Stop. The camera preview and labels use the same mirror setting. Bounds keep the orb inside the viewport and above the composer; the Eyes panel is avoided.

Voice filtering taps the existing conversation microphone after explicit listening activation. Browser noise suppression/echo cancellation remain enabled. A local speech-band tap and adaptive energy gate discard quiet background-only input. The existing Tracky acoustic feature algorithm is reused; it is a lightweight provisional conversational matcher, not measured speaker authentication or reliable source separation of overlapping speakers. This release adds no large trained model/runtime download.

Eyes contains voice learning controls with separate participant consent. Three clean phrases store local acoustic features, never raw audio. HomeServer uses existing Tracky voice fields. Cloud uses account-scoped IndexedDB keys separate from visual samples, with current server recognition consent. Learning/forgetting does not change participant notes, face samples, ElevenLabs cloning or saved API keys. Known-only mode rejects unavailable, unknown or ambiguous voice evidence. Normal mode preserves visitor conversation. Stop commands remain available. An explicitly invited camera introduction can proceed without pretending the speaker is already recognized.

A successful voice match supplies a single-use, message-bound speaker hint to ordinary Chat. Cloud resolves the name against the current owned/active/consented participant. HomeServer accepts the provisional name only on the owner canvas and strips local profile IDs and features from model context; paired apps cannot inject it. Hints grant no identity, data or tool authority. Existing provider, quota, routing, privacy and approval policies still apply. Recognized voice turns enter the existing private Brain timeline. Popup voice learning delegates to the existing embedded Chat owner with origin/window checks and queued-start cancellation.

Verification covers name persistence, canonical record reuse, consent, track replacement, mirrored motion, reduced motion, one voice owner, background rejection, ambiguity, three-sample enrollment, account isolation, one-use context, owner-only backend context, stale permissions, delayed matching cancellation, Stop, existing dictation and the complete Chat canvas. Browser camera/audio fixtures are controlled inputs. Real microphones, noisy rooms, speakers and camera accuracy still need installed hardware testing; no universal noise-removal or biometric accuracy claim is made.
