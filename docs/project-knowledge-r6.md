# R6 — Conversation-scoped Project Knowledge

Select All authorized Knowledge, Knowledge off, an existing Research project or a personal Knowledge folder on the Chat canvas. Apply context explicitly; the settings are keyed to the current owner, lead and saved conversation. Cloud and Chrome share the Cloud conversation choice. Native owner conversations retain their own same-pairing scope choice. Settings never start inference, open a website, create Knowledge records or save a report.

Attach up to six saved browser highlights and completed, explicitly saved Research reports. Attachments are revision-bound references. They leave the typed question intact and are consumed after a successful send. Failed sends retain the draft. A changed conversation clears selected references. Knowledge folders include indexed canonical personal Knowledge; reports require a project/All scope because they have no canonical Knowledge-folder identity.

Each selected source is checked against the current owner, lead, project/folder and source permissions. Exact stale revisions stop for refresh, rather than substituting unrelated sources. Automatic matches remain within the selected scope and the existing context budget. Source blocks use [P#] labels, captured/saved dates, original URLs for highlights and canonical report links. Excerpts remain untrusted data. Independently edited canonical annotation Knowledge is excluded from capture attachment projection; its canonical Knowledge data can be read through the existing folder retrieval.

Cloud resolves a bounded canonical packet per turn. Native owner and current VP3 delegation resolve the same canonical folder/project IDs through their paired Cloud endpoint, rather than treating Cloud IDs as native collection keys. Restricted native local collections remain a separate authority boundary. Revoked app permission, Knowledge opt-out, private conversation settings, disabled synchronization or replaced pairing deny access. Project/folder scopes require current Cloud connectivity. HomeServer advertises `knowledge.context.scoped.r6`; Cloud refuses scoped delegation to an older build and verifies the returned exact-source fingerprint (or explicit Knowledge-off acknowledgement). Native local collection/Knowledge and shared collaboration retrieval do not broaden a scoped turn; model Knowledge/workspace search cannot expand the selected evidence.

Before assistant persistence, the canonical scope and source fingerprints are checked again. A changed source or grant discards the reply; native cancelled turns remove partial user history. The existing Chat and Brain history retain bounded citation receipts and scope metadata. The Brain sidebar shows source links, historical dates and receipt state. Historical receipt state is not a live device heartbeat. Native schema 80 stores preferences only; Cloud upgrade creates chat_knowledge_context_r6. No additional Knowledge/evidence store is introduced. Chrome 22.16.0 retains its identity and connection storage.
