# A5C2 coordinated specialist execution

Prepare a mission in Chat, review its specialist assignments, approve any browser origin separately, then start the reviewed contract. The existing durable dependency scheduler runs at most four workers. Each worker may use only its assigned registered reads: knowledge search, contact search, task listing, or its separately approved browser URL. Model-only workers use a zero-read budget.

Read claims persist before dispatch. The cumulative per-worker budget includes failed and ambiguous calls and is never replenished by retries or restart. Start operations use durable UUID receipts and an exact reviewed revision. Pausing, cancellation, expiry, permission changes and owner browser takeover fence read dispatch and result commits. Permission, pairing, scope and collection changes invalidate the run permanently, including a revoke-and-restore sequence; a new reviewed mission is required.

Outputs have an assigned analysis, sources or document format, bounded title and body, and citation IDs drawn only from actual supplied evidence or completed dependencies. Documents are returned as drafts. Output validation establishes structure and evidence lineage, not factual accuracy. Results remain unverified and require owner review. No specialist writes, shell execution, arbitrary URLs or additional unreviewed workers are available.

`tests/agent_mission_orchestration_a5c2.py` uses real SQLite, the existing scheduler, and audited native read implementations. Only model inference is stubbed. It covers dependency concurrency, duplicate starts, budget exhaustion and interrupted claims, malformed output, source isolation, native owner handling of paired-app missions, expiry, pause/resume, cancellation, permission restoration, pairing rotation, collection scopes, browser grants and takeover. Existing A1/A3/A5/A5B4 and migration tests remain release gates. Real Chromium tests exercise the Cloud and native assignment controls, draft preservation, retry receipts, revision-bound start, and the canonical Brain drawer.

The Windows build includes migration 071 and the authority invalidation feature schema. Deploy packages require schema 71, a real installer, managed-browser certification, exact source provenance and executable checksums. Cloud deployment remains a complete flat webroot ZIP. Deliverables are released only after exact-head PR checks, merge, merged-main checks and package verification pass.
